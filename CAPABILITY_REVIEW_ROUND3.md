# Library capability review — follow-up round, 2026-10-04

This round rechecks all **68 importable libraries** against their current public
APIs, implementations, documented limits and focused existing tests. It follows
the [previous capability review](CAPABILITY_REVIEW.md), which remains unchanged
as a record of its delivered revisions and CI results.

**12 additional libraries were improved**, **44 candidates remain deferred**,
and **12 findings describe deliberate scope boundaries**. Libraries changed
in the previous round were checked for their next gap. Source references below
are pinned to the revisions reviewed in this round.

## Validation

The 12 changed libraries passed local `goml fmt --check`,
`goml test --timeout 300s`, `goml verify --timeout 300s` and `git diff --check`,
using GoML 0.1.57 and Go 1.26.8. `verify` built and tested each example as an
independent consumer through an isolated registry. The existing opt-in
`tabwriter` scaling benchmark remains ignored by the ordinary test run.

Focused checks cover:

- Signed integer roots: truncation toward zero, signed remainders, exact/inexact roots, invalid degrees and magnitude limits.
- Decimal quotient/remainder: signs, scale differences, normalization, zero divisors, representation limits and 192 independent integer-reference vectors.
- CSV comments: record-start recognition, quoted fields, BOM/line endings, fragmentation and record/total byte quotas.
- Go documentation URLs: identifier boundaries, punctuation, bracket balance, escaped HTML, explicit links, output bounds and repeated malformed URL candidates.
- Mail address groups: labels, empty groups, ordering, independent group/member quotas and legacy flat-list behavior.
- LSP completion output: omitted/empty/false/null values, enum bounds, single-line edits, request-position checks and list ordering.
- Multipart discard: partial and empty bodies, fragmented boundaries, exact quotas, source errors, truncation and following parts.
- Binary sentinel collections: incomplete prefixes, sentinel priority, commitment, zero-width progress and shared budgets.
- Property state machines: cleanup after execution panics, setup failure, cleanup failure and preservation of the original panic payload and stack.
- Table alignment: final numeric columns, ragged/empty cells, display widths, copied options, chunk splits, CRLF and output bounds.
- Extended Key Usage: frozen DER vectors, all purpose helpers, unknown/repeated OIDs, canonical encoding and byte/element/depth/arc limits.
- Optional XML fields: missing versus empty values, serializer omissions, namespace matching, strict invalid/unknown content, copied configuration and byte bounds.

Cross-review identified repeated suffix scans in malformed automatic URLs;
the renderer was revised to avoid quadratic rescanning and match Go identifier
boundaries. Review also checked
numeric sign/scale contracts, CSV accounting and the XML/DER/alignment APIs.
A decimal formatting failure in the first CI run was fixed and the final
revision passed CI.

The remaining 56 libraries received API/implementation/test review; their full
runtime suites were not rerun in this round. Historical split manifests and the
pinned verification inventory remain the existing migration and CI baseline.

## Candidates for a later round

These are remaining candidates, not commitments to expand every library:

1. `textproto`: checked header replacement/removal with explicit duplicate ordering.
2. `regexp`: callback replacement with defined callback errors and output budgets.
3. `cache`: batch writes with explicit atomicity, eviction and callback ordering.
4. `x509`: a bounded Subject Alternative Name codec with typed GeneralName handling.
5. `uuid`: an opt-in monotonic v7 generator with clock rollback and counter-overflow rules.
6. `xml`: repeated child mappings after defining cardinality and Serde container behavior.
7. `object`: typed ELF note iteration with independent alignment/endianness fixtures.
8. `datetime`: checked format-pattern parsing with field-conflict and incomplete-date rules.

Larger protocol, platform, numerical and presentation-tree expansions remain
listed above with their required design and validation work.
